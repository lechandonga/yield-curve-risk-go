# 收益率曲线构建与利率风险计量引擎（纯本地）

一套用 Go 实现、完全本地运行的收益率曲线构建、固定现金流利率工具定价、
利率风险计量与在线曲线版本管理引擎。全部行情均为调用方提供的本地模拟
报价，代码中不存在任何网络调用或外部服务依赖。

## 1. 模块结构

| 包 | 职责 |
| --- | --- |
| `internal/marketquote` | 本地报价结构、确定性校验与去重/冲突规则 |
| `internal/curve` | 曲线自举、任意期限折现因子查询、插值/外推、自洽重定价、无套利形态检查 |
| `internal/instrument` | 固定现金流工具定价（PV 与逐笔折现分解） |
| `internal/risk` | 关键期限敏感度、平行/斜率/曲率情景重估、风险对账 |
| `internal/registry` | 在线报价更新、原子发布、不可变版本与历史查询 |
| `cmd/demo` | 纯本地可运行的端到端演示 |

## 2. 报价与曲线约定

### 2.1 报价

- 报价类型：
  - `DEPOSIT`：零息存款。中间价为该期限的**连续复利零息率**，
    即 `DF(t) = exp(-r·t)`。
  - `SWAP`：年付息平价利率互换。中间价 `s` 满足
    `1 = s·Σ_k DF(T_k) + DF(T_n)`（年化固定端，末期允许不足一年的残段）。
- 价格为小数（`0.03` 表示 3%），必须 `BidRate ≤ AskRate`；
  构建统一使用确定性中间价 `(Bid+Ask)/2`。
- 校验时间为批次的 `asOf`；`Policy` 默认：最大报价年龄 15 分钟、
  未来时间戳容忍 30 秒。

### 2.2 确定性脏数据规则

所有输入先按 `(QuoteTime, ID)` 固定排序后再处理，使结果与输入切片顺序
无关。每条被排除的报价都返回带**可区分原因码**的记录，绝不静默择一：

| 原因码 | 含义 | 是否致命 |
| --- | --- | --- |
| `MISSING_ID` | ID 为空 | 是 |
| `DUPLICATE_ID` | 同一 ID 被多条报价使用 | 是 |
| `UNKNOWN_KIND` | 不支持的报价类型 | 是 |
| `INVALID_TENOR` | 期限非有限正数 | 是 |
| `NON_FINITE_RATE` | bid/ask 为 NaN/Inf | 是 |
| `NEGATIVE_SPREAD` | bid 或 ask 为负 | 是 |
| `INVERTED_QUOTE` | bid > ask 买卖价倒挂 | 是 |
| `STALE_QUOTE` | 报价早于 `asOf-MaxAge` | 是 |
| `FUTURE_QUOTE` | 报价时间戳过度超前 | 是 |
| `CONFLICT_QUOTE` | 同类型同期限但价格不同的冲突报价 | 是 |
| `DUPLICATE_QUOTE` | 类型、期限、价格、时间戳完全相同的重复报价 | 否（保留固定排序下的第一条，其余作为 warning 暴露） |

任何致命缺陷都会使整个批次失败并返回 `*marketquote.BatchError`
（在线更新场景包装为 `*registry.UpdateError`），曲线不会被坏数据污染。

### 2.3 曲线构建

- 存款节点直接给定零息率；互换节点按到期日升序逐个自举，
  通过二分法求解期末零息率（残段付款与期末节点在零息空间线性相关）。
- 至少需要一条 `DEPOSIT` 作为短端锚点；互换期限不得短于已建节点。
- 节点间默认 `LINEAR_ZERO`（零息率随时间线性插值），可配置为
  `FLAT_ZERO`（段内零息持平）。

### 2.4 外推策略（显式、稳定、可配置）

- `FLAT`（默认）：报价区间之外零息率保持边界值恒定（短端持首节点、
  长端持末节点），行为明确且稳定。
- `FAIL`：任何超出报价区间的查询返回错误，拒绝隐式外推。
- 非法查询期限（负数/NaN/Inf）始终返回错误。

### 2.5 自洽性保证

曲线构建成功前强制执行两类检查，任一失败则不返回曲线：

- **自洽重定价**：所有存款在其期限重算出的零息率必须等于报价中间价；
  所有互换的曲线隐含平价 `(1-DF(Tn))/ΣDF(Tk)` 必须等于报价中间价。
  默认容差 `RepriceTol = 1e-10`。
- **区间内无套利形态**：在覆盖报价区间的密集网格（默认每周一个点）
  上验证折现因子严格递减且在 `(0,1]`；违反时返回包含两端期限与 DF 的
  显式错误。容差 `ArbTol = 1e-10`。

## 3. 定价与风险口径

### 3.1 定价

- 固定现金流工具：`PV = Σ Amount_k · DF(T_k)`，支持任意固定付款计划
  （`instrument.Bond` 可便捷构造年付息含本金摊还债券）。
- `instrument.Price` 返回逐笔流的 `DF` 与现值分解，便于解释。
- 同一（报价快照, 配置）下定价为纯函数，逐位可复现。

### 3.2 关键期限敏感度与情景

- 冲击标的为**连续复利零息率**，单位为绝对小数（1bp = `0.0001`），
  默认采用**单边向上**冲击。
- 关键期限冲击为无尖峰的分段常值平移：关键期限 `k_i` 的桶为
  相邻关键期限中点构成的半开区间 `(midLeft, midRight]`，
  首桶向左延伸到 0、末桶向右无限延伸。所有桶恰好划分整条期限轴，
  因此**每个关键期限各冲一次之和恒等于一次全曲线平行冲击**。
- 情景：
  - `PARALLEL`：零息率整体平移 `Size`。
  - `SLOPE`：在 `PivotShort`（-Size）到 `PivotLong`（+Size）之间线性倾斜。
  - `CURVATURE`：蝶式，两端 +Size、`PivotMid` 处 -Size，锚点间线性。

### 3.3 风险对账口径与容差

`risk.Analyze` 每次同时计算平行重估变化与各关键期限敏感度并强制对账：

```
| Σ_i ΔPV_key_i − ΔPV_parallel | ≤ ReconcileAbsTol + ReconcileRelTol·|PV_base|
```

默认 `ReconcileAbsTol = 1e-8`、`ReconcileRelTol = 1e-10`。该差异仅来自
浮点求和次序；对账失败时返回 `*risk.ReconcileError`，明确给出平行变化、
关键期限之和、差异量、基准 PV 与实际容差，绝不静默取近似值。
注意：+1bp 与 -1bp 的差属于二阶凸性，不属于对账恒等式范围。

## 4. 在线更新与并发一致性模型

- `registry.Version` 一经发布即不可变（曲线、报价快照、asOf、warning 全部固化）。
- 更新流程为**全有或全无**：校验 → 自举 → 自洽检查全部在锁外完成；
  只有完整新曲线构建成功后才进入发布临界区。
- 发布在同一把发布锁内先追加不可变历史、再原子切换 `current`，
  保证“能读到版本 N 就一定能在历史中查到 N”。
- 读取方只能看到完整的旧版本或完整的新版本：`Current()` 为原子指针读，
  历史查询走 RLock + append-only 快照，不存在半更新状态。
- 坏批次：保留上一可用版本，返回 `UpdateError`（含全部致命原因），
  失败不消耗版本号、不产生部分应用。完全重复报价随版本以 warning 暴露。
- 并发更新由发布互斥串行化，读多写少场景下读路径不持写锁；
  并发测试在 `-race` 下通过，且无死锁。

## 5. 本地验证方法

```bash
# 普通全量测试（日志含业务分组、用例名与结果）
go test ./... -v

# 并发用例的竞态检测（registry 并发更新/读取/历史查询）
CGO_ENABLED=1 go test -race ./... -v

# 端到端演示（纯本地报价，无任何网络 I/O）
go run ./cmd/demo
```

测试覆盖业务一览：

- 脏报价与冲突：空 ID/重复 ID、未知类型、非法期限、NaN/Inf、
  负价、买卖倒挂、过期/未来时间戳、冲突报价（致命）与完全重复（非致命），
  以及去重结果与输入顺序无关的确定性。
- 曲线自洽与无套利：存款/互换精确重定价、区间内 DF 单调、
  任意期限插值、FLAT/FAIL 外推、缺少锚点失败、乱序快照逐位复现。
- 定价与风险：固定现金流与平价债券定价、关键期限敏感度对账、
  容差超限显式报错、平行/斜率/曲率重估方向与凸性、非法情景参数、
  重复计算逐位一致。
- 在线更新：版本发布/历史查询/不可变、脏数据/过期/冲突批次失败回退、
  失败后版本号不被消耗、并发更新（含半数坏批次）+ 并发读取（读时实时
  风险对账）+ 历史查询在 race 检测下零半更新。
